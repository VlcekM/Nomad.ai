# Nomad.ai

A lightweight native Windows client for Claude Code sessions, written in C# on .NET 10 and
Avalonia 11 and published with NativeAOT.

Nomad.ai does not run models itself. Each session starts the installed `claude` CLI as a child
process and drives it over the stream-json protocol on stdin/stdout. The CLI's sign-in, settings,
hooks, MCP servers and session storage are all used as they are. The one direct call is read-only:
plan usage limits, fetched like Claude Code's `/usage` with the CLI's stored claude.ai sign-in. The look follows the Code tab of
the Claude desktop app from before its late-2026 restyle (see `DESIGN.md`).

## Requirements

- Windows 10 or 11, x64.
- The Claude Code CLI, installed and signed in (`claude` on `PATH`, or its full path set under
  Settings → Claude Code). Nomad.ai never signs in for you; run `claude` once in a terminal first.
- To build: the .NET 10 SDK. A NativeAOT publish also needs Visual Studio's C++ build tools
  ("Desktop development with C++").

## Run and build

```powershell
dotnet run --project Nomad.App          # debug build
dotnet test Nomad.Core.Tests            # protocol parsing and session title tests
```

Publish a single native executable:

```powershell
dotnet publish Nomad.App -c Release -r win-x64
# -> Nomad.App\bin\Release\net10.0\win-x64\publish\Nomad.ai.exe
```

The AOT linker finds the C++ tools through `vswhere.exe`. If the publish fails with "vswhere is not
recognized", put the Visual Studio Installer folder on `PATH` first:

```powershell
$env:PATH = "C:\Program Files (x86)\Microsoft Visual Studio\Installer;" + $env:PATH
```

## Install and update

Each release on GitHub ([VlcekM/Nomad.ai](https://github.com/VlcekM/Nomad.ai/releases)) has two downloads:

- **`Nomad-win-x64-Setup.exe`** installs Nomad.ai for your Windows user, without admin rights, into
  `%LOCALAPPDATA%\Nomad`, with Start menu and desktop shortcuts and an entry in Settings → Apps for
  uninstalling. This copy updates itself.
- **`Nomad-win-x64-Portable.zip`** runs from any folder and never updates itself; Settings → Updates
  links to the releases page instead.

An installed Nomad.ai checks GitHub at startup and every 6 hours ([Velopack](https://velopack.io)).
With **Install updates automatically** on (the default), a new version is downloaded in the background
and Nomad.ai restarts into it, but only when that interrupts nothing: no turn or phone session
running, no prompt being typed, no session connected through Remote Control. Otherwise a **Restart to
update** chip appears next to the gear in the sidebar footer, and the update is installed when Nomad.ai
closes. With the setting off, the chip offers the new version with its release notes and installs it
on click. Settings → Updates shows the version, both switches (the other one includes pre-releases),
a **Check for updates** button and every release with its notes. The check reads GitHub anonymously,
so it needs the repository to be public.

Setup empties `%LOCALAPPDATA%\Nomad` before it installs, and uninstalling deletes it, shortcuts and
the Apps entry included. Both take the Claude font cache in `%LOCALAPPDATA%\Nomad\fonts` with them
(Nomad.ai unpacks the fonts again at its next start); updates leave it alone. Builds from before the
move to `%LOCALAPPDATA%\NomadData` kept their scratch folders in `%LOCALAPPDATA%\Nomad\scratch`, so
move anything worth keeping out of there before the first install. Settings (`%APPDATA%\Nomad`) and
scratch folders (`%LOCALAPPDATA%\NomadData`) stay.

### Cutting a release

1. Add a `## v<version>` section at the top of `CHANGELOG.md` with a few bullets and push it. Local
   builds take their version from the newest heading.
2. Run the **Release** workflow (`.github/workflows/release.yml`) with that version, from the Actions
   tab or with `gh workflow run release.yml -f version=0.1.0` (add `-f prerelease=true` for a
   pre-release, which is not marked Latest).

The workflow checks the version, that the tag `v<version>` is new and that the changelog section is
not empty, publishes `Nomad.App` with NativeAOT on `windows-latest` (`-p:Version=<version>`), packs
it with `vpk` (pack id `Nomad`, channel `win-x64`, the tent icon) and creates the `v<version>`
release with Setup, the portable zip, the update feed (`releases.win-x64.json` and the `.nupkg`) and
`SHA256SUMS`. The changelog section is the release notes, followed by GitHub's generated notes since
the previous tag.

## What it does

- **Sessions.** The sidebar lists the sessions stored by the CLI in `%USERPROFILE%\.claude\projects`,
  newest first, with search. Opening one shows its history; sending a prompt resumes it in a new CLI
  process (`--resume`). New sessions get a short title generated by the CLI. Sessions with a running
  CLI process are listed under **Alive**, the rest under **Idle**. A process quiet for an hour is
  ended and its session moves to Idle; right-click a session to make it idle or alive by hand, to
  archive it, or to delete it (into the Recycle Bin). The sliders icon groups the Idle list by date
  (the default), by folder or not at all, and shows archived sessions; a click on a group heading folds
  it, and the Alive heading folds its list. Sessions untouched for 24 hours (Settings, at least 1) are
  archived on their own. On the right of a row, the working mark shows a running turn, a yellow dot a
  question or permission waiting for you, and a blue dot a finished turn not seen yet. Before them, in GitHub's
  colours, the session's pull request (from its branch, or the last one it mentions) and its issue (closed by
  that pull request, the last one it mentions, or a number in its branch or title); a click opens either. They come
  from the `gh` CLI with your own sign-in, cached for a few minutes. Sessions another Nomad window
  or a terminal runs are listed as Alive with a laptop icon.
- **Transcript.** Streaming markdown (headings, lists, tables, code blocks, inline code, links),
  collapsible activity groups ("Ran 2 commands", "Edited a file", with +/− counts) that hold the tool
  calls and the thinking between them (as the desktop app: only text ends a group), a "Thought process"
  line for thinking outside a group, an error card, and, while a turn runs, a working row (animated
  mark, what Claude is doing, elapsed time). The mark is the desktop app's own animation per activity
  (thinking, reading, searching, running code, writing, waiting for you), read at start from the installed
  Claude app; without it, a pixel spinner. Background-task notifications show as a muted notice line,
  not as a prompt. New text fades in as it streams. Hovering a prompt
  shows its seen mark (✓ sent, ✓✓ picked up), its age, and Copy, Rewind (cut the conversation back
  to before it and put it in the composer; files are not restored) and Fork (a new session with the
  conversation through that turn).
- **Window.** Middle-click a scrollable area to autoscroll, as in a browser. With "Close to the tray"
  (Settings › General) the close button hides Nomad.ai to the notification area; its icon brings it back.
  Switching the model of a conversation with history asks first, since its cache does not carry over.
- **Prompt suggestions.** After a turn, Claude Code guesses the next prompt (`--prompt-suggestions`);
  it shows as grey text in the empty composer with a Tab hint. Tab, → or a right-click puts it in to
  edit or send, Esc dismisses it, typing replaces it. Settings › Claude Code turns it off.
- **Permissions.** Tool requests appear as a card with Allow, Allow for session and Deny (Enter
  allows, Esc denies), shown with the command or a small diff. Answered cards shrink to one line.
  When Claude asks a question (AskUserQuestion), its options and a free-text answer appear in a
  card with Submit and Skip.
- **Remote Control.** A running session can be continued from the Claude mobile app or
  claude.ai/code (the phone icon in the status row; on by default, see Settings). Nomad turns it on
  with the CLI's `remote_control` control request once a session has a name, keeps the claude.ai
  session across restarts (`reattach_session_id`), and runs the CLI with `--replay-user-messages`
  so prompts typed on the phone appear in the transcript (with a phone mark). Sessions with Remote
  Control on are not ended by the idle timeout. Permission prompts appear in Nomad as usual.
- **Starting sessions from the phone.** For each folder under Settings → Claude Code → Start sessions
  from the phone, Nomad keeps `claude remote-control --spawn same-dir` running, so the Claude app
  can start new sessions there. Those sessions belong to that server's child processes, so Nomad
  finds them (in its job object), shows them under Alive with a phone icon and follows their
  transcript live; the composer returns when they end, or at once with **Continue here**, which
  ends the phone's process and resumes the session in Nomad, attached to the same claude.ai session.
  The CLI asks two one-time questions (turning Remote Control on, trusting the folder) that need a
  terminal: **Set up** opens one running `claude remote-control` in the folder. Only one server can
  serve a folder, so a `claude remote-control` in a terminal there makes Nomad's retry until it ends.
- **Status row.** Folder chip (recent folders, "Open folder…", or "No folder", which uses a fresh
  scratch folder), permission mode (Auto, Manual, Accept edits, Plan, Bypass permissions), a chip
  per model (Fable 5.1, Opus 5.5, Sonnet 5.5, Haiku 5.5), a filled effort slider (Low to Max), and
  a ring showing how much of the context window the session uses. Clicking the current model, or
  the chevron, opens the full picker with fast mode. Clicking the ring shows the plan usage limits
  (session, weekly, weekly per model, with reset times), refreshed after each turn. Weekly bars carry
  the even pace behind them (where using the week up evenly, 24/7, would be by now) and a forecast:
  when the limit runs out at this week's rate, or how much is used by the reset. The last answer is
  shared between windows (`usage-cache.json`) and shown, marked stale, when the endpoint refuses.
- **New session.** The latest projects as cards (branch, changed files, the last commits, when Claude
  last worked there); a click works there. What is typed (and attached) on the new-session page stays
  while other sessions are open, and its text across restarts.
- **Composer attachments.** Above a dashed rule, apart from the text: images named underneath, a click
  shows one large (← → step through, Esc or a click closes); images in sent prompts open the same way.
- **Session search** (Ctrl+T, or the menu): finds sessions by title or by anything said in them (your prompts and
  Claude's replies, not tool output), archived ones included. Each result shows whether it is alive, idle or
  archived, a filter for each, and how long ago it was active (up to 30 days, then the date). The transcripts are
  read in the background the first time; matches come in as they are.
- **Side panel** (Ctrl+Shift+B, the panel button in the title bar, or the strip on the right edge): the
  folder's git state and latest commits (open it in Explorer or a terminal), the session's subagents
  (duration, last status; a click opens a subagent's own conversation), the context window, plan usage
  and the MCP servers (configured ones before the CLI starts, then their connection state). Each card folds,
  and the sliders button at its bottom right turns cards off and on; drag its left edge to resize it, as the sidebar's right edge (double-click for the default width).
- **Paths in replies.** A URL in `inline code` opens with a click; a file or folder path that exists
  (absolute, or relative to the session's folder, `:line` suffixes ignored) with Ctrl+click shows it
  selected in Explorer. Right-click either for Show in Explorer, Open and Copy.
- **Settings** (gear in the sidebar, or Ctrl+,): interface and code fonts, interface and transcript
  text size, transcript width, display name; CLI path and the default model, mode and effort for
  new sessions. Changes are saved at once. With the Claude desktop app installed, Anthropic Sans and
  Anthropic Mono are offered too: they are unpacked from the app's WOFF2 files into
  `%LOCALAPPDATA%\Nomad\fonts` and never shipped with Nomad.ai. The Updates page is described under
  Install and update.

### Memory and rendering

Nomad.ai draws with the GPU through ANGLE over Direct3D 11, which is far faster than Skia's software
renderer. It falls back to software rendering only when no GPU is usable. ANGLE costs about 10 MB
of private working set over software (most of the rest is the shared graphics driver); native
OpenGL and Vulkan were measured at 2-3x the memory.

### Keyboard

| Keys | Action |
|------|--------|
| Enter / Shift+Enter | Send / new line; while Claude works, Enter queues the prompt and Ctrl+Enter (or Ctrl+click on Send) stops Claude and sends it now |
| Esc | Deny a pending permission (a running turn stops only with the Stop button) |
| Ctrl+1 … Ctrl+9 | Open the sidebar's sessions, top to bottom (hold Ctrl to see their numbers) |
| Ctrl+Shift+1 … Ctrl+Shift+4 | Switch model |
| F1 … F4 | Switch model, Fable to Haiku (off by default: Settings › Claude Code; F2 then no longer renames) |
| Ctrl+N | New session |
| Ctrl+T | Search sessions: chat titles and conversations, alive, idle and archived (↑↓, Enter opens, Esc closes) |
| Ctrl+F | Find in the chat: marks every match (Enter / Shift+Enter or F3 / Shift+F3 step through them, Esc closes) |
| Ctrl+B | Show or hide the sidebar |
| F2 | Rename the current session (also a double-click or right-click on its row) |
| Ctrl+Shift+B | Show or hide the side panel (or click the strip on the window's right edge) |
| Ctrl+, | Settings |

### Files

| Path | Contents |
|------|----------|
| `%APPDATA%\Nomad\settings.json` | Nomad.ai settings, recent folders, window placement |
| `%APPDATA%\Nomad\releases-cache.json` | The GitHub release list and its ETag (Settings → Updates) |
| `%APPDATA%\Nomad\usage-cache.json` | The last plan usage answer, shared between windows |
| `%LOCALAPPDATA%\Nomad\` | The Setup install (`current\` is replaced by each update) and the Claude font cache (`fonts\`) |
| `%LOCALAPPDATA%\velopack\velopack_Nomad.log` | Velopack's log: update checks, downloads, applied updates, uninstall |
| `%LOCALAPPDATA%\NomadData\scratch\` | Folders for sessions started with "No folder" |
| `%USERPROFILE%\.claude\projects\` | Session transcripts (owned by the CLI; Nomad.ai only reads them, except that Rename appends a `custom-title` record, as `/rename` does) |

## Project layout

| Project | Role |
|---------|------|
| `Nomad.Core` | CLI process host (Job object, so children die with Nomad.ai), stream-json protocol records with source-generated JSON, `IAgentBackend` / `ClaudeCodeBackend`, session store and history reader, settings, GitHub release list |
| `Nomad.App` | Avalonia UI: frameless window, sidebar, session view, own Markdig-to-Avalonia renderer, menus, settings dialog, self-update |
| `Nomad.Probe` | Console test bench that runs Nomad.Core against the real CLI |
| `Nomad.Core.Tests` | A few xUnit tests over captured stream-json fixtures and session titles |

## Probe

The probe drives the real CLI and prints every event. Without `--full` it runs the CLI with a small
tool set and no MCP servers or skills, so test turns stay cheap.

```powershell
dotnet run --project Nomad.Probe -- <scenario> --cwd <folder> [--model claude-haiku-5-5] [--out transcript.jsonl] [--full]
```

Scenarios: `pong`, `write-allow`, `write-deny`, `interrupt`, `multiturn`, `controls`, `title`,
`sessions`, `history <file>`, `releases [owner/repo]` (the GitHub release list, read twice: the second
read should be a free 304 from the ETag cache).

## Development flags

`Nomad.ai.exe` accepts a few flags for scripted checks and screenshots:

| Flag | Effect |
|------|--------|
| `--dev-cwd <folder>` | Folder of the initial new session |
| `--dev-prompt "<text>"` | Send this prompt on start |
| `--dev-model <id>` | Model for the initial session |
| `--dev-session <id>` | Open this stored session on start |
| `--dev-screenshot <png>` | Render the window to a PNG and exit… |
| `--dev-after <seconds>` | …this many seconds after start (default 5) |
| `--dev-wait-turn` | …or as soon as the first turn has finished |
| `--dev-size <W>x<H>` | Initial window size (window placement is then not saved) |
| `--dev-menu model\|mode\|folder\|branch\|plus\|usage\|remote\|update\|list\|row` | Open a menu (the update chip's prompt, the sidebar's list options, the first Idle row's context menu) before the screenshot |
| `--dev-settings-open [claude\|updates]` | Open the settings dialog (or that page) before the screenshot |
| `--dev-side-panel` | Open the side panel (not saved) |
| `--dev-queue "<text>"` | Put a prompt in the queue above the composer (repeatable) |
| `--dev-settings <path>` | Use this settings file |
| `--dev-lean` | Small CLI tool set, no MCP servers or skills |
| `--dev-phone` | Start the phone folders' Remote Control servers (scripted runs skip them) |
| `--dev-expand` | Expand tool groups and thinking before the screenshot |
| `--dev-answer allow\|session\|deny\|pick` | Answer every permission request automatically (questions get their first options; `pick` only selects them) |
| `--dev-set textSize=Large` | Change an appearance setting live (`textSize`, `width`) |
| `--dev-stop-after <seconds>` | Press Stop this long after the dev prompt was sent |
| `--dev-key <gesture> <seconds>` | Press a key (e.g. `Ctrl+B`) on the focused control this long after start |
| `--dev-drag x1,y1,x2,y2 <seconds>` | Drag with the left button between two window points (sent to Nomad's window only; the cursor never moves) |
| `--dev-drag-ctrl` | Hold Ctrl during `--dev-drag` (for Nomad's thread only, never the real keyboard); in a screenshot run, Show in Explorer only logs the path |
| `--dev-compose "<text>"` | Put text in the composer (`\n` for new lines) |
| `--dev-search "<query>"` | Open the session search (Ctrl+T) with this query |
| `--dev-find "<text>"` | Open the find bar (Ctrl+F) with this text |
| `--dev-paste-image <file>` | Attach an image (or any file, as a chip) to the composer, as a paste would; repeatable |
| `--dev-log <file>` | Append every line to and from the CLI to a file (`> ` sent, `< ` received) |
| `--dev-cli-debug <file>` | Have the CLI write its debug log to a file (`--debug-file`) |
| `--dev-update-source <folder>` | An installed build updates from this local `vpk` output folder instead of GitHub |
| `--dev-update-after <seconds>` | The first update check this long after start, not at once (to catch the update chip folding in) |
| `--dev-releases-repo <owner/repo>` | List another repository's GitHub releases on the Updates page |

Example:

```powershell
Nomad.ai.exe --dev-cwd C:\temp\k --dev-model claude-haiku-5-5 --dev-lean `
  --dev-prompt "Reply with exactly: pong" --dev-wait-turn --dev-after 60 --dev-screenshot C:\temp\pong.png
```
